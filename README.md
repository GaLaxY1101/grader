# Grader

**Тема роботи:** «Система автоматизованої перевірки лабораторних робіт на основі підходів CI/CD».

English version: [README.en.md](README.en.md).

## Короткий опис

Grader — вебсистема для ведення навчальних курсів і автоматичної перевірки програмних
лабораторних робіт. Викладач створює курс і завдання з тестами. Студент надсилає розв'язок
у браузері, і система перевіряє його так само, як перевіряють код у промисловій розробці:
код потрапляє в окремий Git-репозиторій, а **GitLab CI/CD** збирає його й запускає тести в
ізольованому Docker-контейнері. Після цього студент бачить результат кожного тесту
(очікуване / отримане значення), а викладач — оцінки всієї групи.

Основні можливості:

- курси, завдання, дедлайни, файли до завдань і робіт, архів курсів, шаблони курсів;
- три ролі: **студент**, **викладач**, **адміністратор**; єдиний вхід через Keycloak;
- автоматична перевірка коду мовами **Python** і **C/C++** через GitLab CI/CD;
- попередня перевірка компіляції ще до надсилання в ізольованому середовищі;
- детальний звіт за тестами з налаштованим рівнем деталізації для студентів;
- журнал оцінок з експортом у Excel, повернення роботи на доопрацювання;
- **генерація тестів за допомогою локальної LLM** (Ollama): модель пише тести, система
  перевіряє їх на еталонному розв'язку та на штучно зіпсованих версіях коду (мутантах),
  а потім просить модель виправити тести. Дані студентів не покидають сервер;
- масовий імпорт студентів і груп з файлу `.xlsx`.

### Архітектура

| Компонент | Технологія |
|---|---|
| Бекенд (REST API) | Java 25, Spring Boot 4, PostgreSQL 16, Flyway |
| Фронтенд | Next.js 14, TypeScript, Material UI ([окремий репозиторій](https://github.com/GaLaxY1101/grader-frontend)) |
| Автентифікація | Keycloak 26 (OpenID Connect) |
| Перевірка робіт | GitLab CE 16.9 + GitLab Runner (Docker executor) |
| Генерація тестів | Ollama, модель `qwen2.5-coder:3b` |
| Ізольоване середовище | Docker-образи `grader-sandbox-cpp`, `grader-sandbox-py` (без мережі, з обмеженнями ресурсів) |
| Файли | S3-сумісне сховище |

## Встановлення

Уся система запускається однією командою через Docker Compose. Встановлювати вручну
потрібно лише Docker і Git; бази даних, Keycloak, GitLab, LLM та інші компоненти
завантажуються як контейнери автоматично.

### Необхідне програмне забезпечення

| Що | Вимога |
|---|---|
| ОС | Linux (рекомендовано Ubuntu 22.04/24.04) або Windows 10/11 з Docker Desktop (WSL 2) |
| Docker | Docker Engine 24+ з плагіном Docker Compose v2 |
| Git | будь-яка актуальна версія |
| Обладнання | 4+ ядра CPU, 12 ГБ RAM, 30 ГБ вільного місця на диску |
| Мережа | доступ до інтернету під час першого запуску та для CI-завдань |
| Браузер | Chrome, Firefox або Edge актуальної версії з доступом до інтернету (редактор коду завантажується з CDN) |
| Необов'язково | GPU NVIDIA з `nvidia-container-toolkit`: генерація тестів приблизно в 10 разів швидша |

### Порядок встановлення

1. Завантажити обидва репозиторії в одну теку:
   ```bash
   mkdir grader && cd grader
   git clone https://github.com/GaLaxY1101/grader.git grader
   git clone https://github.com/GaLaxY1101/grader-frontend.git grader-frontend
   cd grader
   ```
2. Створити файл налаштувань і заповнити його:
   ```bash
   cp .env.example .env
   ```
   У `PUBLIC_HOST` вказати адресу сервера, яку користувачі відкриватимуть у браузері
   (`localhost` для локального запуску). Кожне значення `change-me` замінити випадковим
   рядком, наприклад з `openssl rand -hex 32`.
3. Запустити систему:
   ```bash
   docker compose -f compose.server.yaml up -d --build
   ```
   Перший запуск триває 10–20 хвилин: збираються образи, завантажується LLM-модель
   (~2 ГБ), ініціалізується GitLab.
4. Перевірити, що бекенд працює: `curl http://localhost:8080/actuator/health` має повернути
   `{"status":"UP"}`.
5. Підключити GitLab для перевірки робіт. Це одноразовий крок: створити токен і
   зареєструвати runner. Точні команди наведено в [DEPLOY.md](DEPLOY.md), крок 5.

Після цього система доступна за адресою `http://PUBLIC_HOST:3000`.

Детальна інструкція для сервера, зокрема типові проблеми, безпека, резервне копіювання й
оновлення, міститься в [DEPLOY.md](DEPLOY.md).

### Демонстраційні облікові записи

| Роль | Логін | Пароль |
|---|---|---|
| Адміністратор | `admin@grader.ua` | `Admin123!` |
| Викладач | `teacher@grader.ua` | `Teacher123!` |
| Студент | `student@grader.ua` | `Student123!` |

На реальному сервері ці облікові записи слід вимкнути (адмінпанель Keycloak →
realm `university-grader` → Users).

## Інструкція користувача

Інтерфейс англомовний, тому назви кнопок і розділів нижче наведено так, як вони
відображаються на екрані.

### Вхід

Відкрийте `http://PUBLIC_HOST:3000` і натисніть **Sign in with Keycloak**. Уведіть логін і
пароль. Система сама визначить вашу роль і покаже відповідне меню. Щоб вийти, натисніть
значок виходу у верхньому правому куті.

### Студент

1. **My Courses** — список курсів, на які вас записано. Відкрийте курс, щоб побачити його
   завдання.
2. Відкрийте завдання та прочитайте умову й прикріплені файли.
3. Залежно від типу завдання:
   - **програмний код** — напишіть розв'язок у вбудованому редакторі (у ньому вже є
     заготовка функції) і натисніть **Submit**. Перед надсиланням система перевірить, що код
     компілюється; якщо ні, з'явиться вікно з помилками компілятора;
   - **файли** — перетягніть файли в область завантаження і надішліть їх.
4. Статус спроби змінюється з **Pending** / **Running** на **Passed** або **Failed** приблизно
   за хвилину. Відкрийте спробу, щоб побачити, які тести пройдено, а які ні, і що очікувалось.
   Обсяг деталей визначає викладач.
5. Можна надсилати нові спроби. Якщо викладач повернув роботу на доопрацювання, у завданні
   з'явиться його коментар.
6. **Archive** — завершені курси.

### Викладач

1. **Courses** → **Create Course**: створіть курс (назва, навчальний рік, семестр) або
   створіть його з шаблону. **Manage Students** — додати до курсу студентів або цілі групи.
2. У курсі натисніть **+ Add**, щоб створити завдання: назва, опис, максимальна оцінка,
   дедлайн і тип (**Code only**, **Files only**, **Code + files**).
3. Для автоматичної перевірки ввімкніть **Enable Code Check** і заповніть:
   - **Language** — Python або C++;
   - **Function Signature / Template Code** — заготовка, яку студент побачить у редакторі;
   - **Reference Solution** — ваш еталонний розв'язок (студентам не показується);
   - тести — pytest для Python (`assert actual == expected`), макроси `TEST_CASE` /
     `EXPECT_EQ` для C++;
   - **Student feedback** — скільки деталей тестів бачить студент (повний звіт, лише назви
     тестів або лише підсумок).
4. **Generate tests with AI** — система сама згенерує тести за умовою завдання, перевірить їх
   на еталонному розв'язку й покаже хід роботи. Готові тести можна вставити у форму та
   відредагувати.
5. Під час збереження система перевіряє, що тести компілюються разом з еталонним розв'язком.
6. У завданні відображаються всі роботи студентів. Відкрийте роботу, щоб переглянути код,
   звіт тестів і журнал CI. Тут же можна поставити оцінку або повернути роботу на доопрацювання
   з коментарем.
7. Вкладка **Grades** курсу — журнал оцінок з експортом у Excel.
8. **Templates** — шаблони курсів із завданнями для повторного використання.
   **Archive Course** — перенести завершений курс в архів (його можна відновити).

### Адміністратор

Має всі можливості викладача, а також розділ **Users & Groups**:

- **Users** — створення, редагування та видалення користувачів і призначення ролей;
- **Groups** — академічні групи та їхній склад; кнопка **Bulk Import** — масовий імпорт
  студентів і груп з файлу `.xlsx`;
- **Students** — список усіх студентів.
